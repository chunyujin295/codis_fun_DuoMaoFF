# 多毛记：私人猫咪收藏册

## 已确认需求

- 整站采用私人猫咪收藏册风格：奶油纸张、墨黑超大标题、荧光贴纸、错位照片、手写批注；延用用户提供的猫爪 Logo。
- 照片与视频原文件保存在 Linux 物理机硬盘，SQLite 保存媒体索引、描述、猫咪关联与拍摄时间。用户不要求把二进制文件塞进 SQLite。
- 管理员上传后需要真实预览、明确成功或失败反馈；容器重建后保留媒体与数据库，并提供备份和部署核查说明。

## 实现范围

- 首页、全站导航、页脚、相册、猫咪、日记、时间线统一视觉，兼容手机与减少动画设置。
- 相册按服务端分页和筛选加载，图片使用缩略图，灯箱打开原图，视频支持 Range 播放。
- 统一 /DuoMaoFF 基础路径下的 API、认证与媒体地址。
- 上传接口检查登录、文件大小和类型；先落盘再登记索引，失败清理本次文件；照片生成缩略图。
- Linux Docker 配置明确持久卷、数据库绝对路径和目录权限；不自动覆盖线上已有数据库。

## 决策理由与边界

- 大量媒体采用磁盘原文件 + SQLite 索引，便于流式读取视频与备份，避免数据库承担大视频二进制存储。
- frp 只影响访问带宽、连接和上传超时，不能替代持久卷或备份。
- 本地验证不等于已核验 Linux 线上磁盘、frp 或反向代理配置。上线前需要按部署文档核查。
- 上传有可配置的单文件上限；本轮不包含跨连接断点续传、视频转码、对象存储或多节点部署。
